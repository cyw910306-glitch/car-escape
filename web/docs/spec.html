2아키텍처와 모듈 책임

다섯 모듈로 나뉘고, 모듈 사이의 약속은 core/Contract.kt 한 파일에 모았습니다. 게임 로직은 Android 에 의존하지 않는 순수 Kotlin 이라 차 없이 단위 테스트로 검증합니다.

:gameKotlin JVM게임 엔진 EscapeGame, 퍼즐 판정 PuzzleRun, 에피소드, 충전 시간 추정 ChargeClock, 마이 차고 규칙, 출발 금고 메모:core

연동 규칙

  • capability 먼저. 모든 입력은 capability 조회에서 읽기 가능(READ 또는 READ_WRITE)으로 나온 것만 구독합니다. 지원되는 입력 집합은 supportedInputs 로 엔진에 전달되고, 엔진은 없는 입력의 퍼즐을 다른 퍼즐로 바꿉니다.
  • 재시도. Pleos 서비스 연결 완료 콜백이 공개 API 에 없어, 실패한 조회는 1.5초 간격으로 3번까지 다시 시도합니다.
  • 수명 주기. 액티비티 onStart 에 구독을 시작하고 onStop 에 모두 해제한 뒤 무드등을 원복합니다. 주행 제한 리스너만 ViewModel 수명을 따라가, 시스템이 앱을 가린 동안의 출발도 놓치지 않습니다.
  • 값 정규화. 창문 원시값은 capability 의 최소·최대로 0~100% 로 바꿉니다. 열선 최대 단계도 capability 에서 읽어 목표 단계가 그 안에 들도록 맞춥니다.
  • 무드등 원복. 원래 스위치, 색, 밝기 세 값을 모두 읽은 영역만 바꾸고, 종료, 주행, 앱 이탈 때 그 값으로 되돌립니다.
  • 런타임 권한. release 첫 실행 때 android.car.permission.CAR_SPEED, CAR_ENERGY 를 요청합니다. 허용되면 게이트웨이를 다시 시작해 구독을 새로 겁니다.

5퍼즐 판정 규칙과 안전 상한

판정은 game/Puzzles.kt 의 PuzzleRun 이 맡습니다. 퍼즐을 시작한 순간의 차 상태가 기준선이며, 그때 이미 켜져 있던 입력은 세지 않습니다. 유지형 퍼즐이 시작부터 정답 상태면 한 번 벗어났다가 다시 맞춰야 인정합니다.

미션입력통과 조건안전 상한
창문 금고창문 위치목표의 ±10% 안에서 2초 유지목표는 30, 50, 70% 뿐. 2열 창문은 절반 이하
쌍둥이 창문운전석과 조수석 창문둘 다 20~80% 안이고 서로 10% 이내, 2초 유지완전 개방, 완전 닫힘은 정답이 아님
독서등 등대독서등켜진 시간이 0.6초 미만이면 짧게, 이상이면 길게. 패턴 일치2.5초 쉬면 입력을 지우고 처음부터
깜빡이 암호방향지시등왼쪽, 오른쪽 순서 일치. 틀리면 처음부터1화에는 넣지 않음(충전소 대기 줄 혼란 방지)
기억 금고방향지시등8초 + 개수 x 0.7초 동안 보여 준 뒤 숨김. 숨긴 뒤의 입력만 인정보여 주는 시간이 지시 음성보다 길게 잡혀 있음
따뜻한 핸들핸들 열선목표 단계에서 1.5초 유지목표는 차가 알려 준 최대 단계 이내
따뜻한 의자운전석 시트 열선목표 단계에서 1.5초 유지위와 같음
와이퍼 인사앞유리 와이퍼켜짐 → 꺼짐을 한 번으로 세고, 2초 조용하면 횟수 판정목표 최대 3회. 다시 시도까지 합쳐 6회면 다음 금고로 넘어감(건너뛰기로 계산)
수수께끼 금고창문, 열선, 와이퍼덧셈·뺄셈의 답만큼 조작. 창문은 10칸 중 답의 칸만(±4%)안쪽 퍼즐의 상한을 그대로 따름
연쇄 금고서로 다른 부품 2~3단계정해진 순서대로. 각 단계는 앞 단계가 남긴 상태에서 시작와이퍼 단계는 넣지 않음. 지원되는 단계만 남김
찰칵앞좌석 안전벨트풀림 → 채움으로 바뀐 것만 인정. 릴레이는 순서가 틀리면 처음부터뒷좌석 벨트는 대상이 아님(카시트 고정 가능성)
번개 금고위 퍼즐에 붙는 시간 제한제한 시간 안에 풀면 번개 배지실패해도 퍼즐은 계속. 실패 조건이 아님

차에 없는 부품의 대체

  • 에피소드를 시작할 때 substitute() 가 지원되지 않는 입력의 퍼즐을 지원되는 입력의 기본 퍼즐로 바꿉니다.
  • 2열 창문이 없거나 창문 잠금이 켜져 있으면 같은 창문 미션을 앞좌석 창문으로 옮깁니다.
  • 두 번째 와이퍼 퍼즐은 다른 후보가 없을 때만 넣습니다.
  • 연쇄 금고는 지원되는 단계만 남깁니다.

구현·테스트 대체 규칙은 SubstitutionTest, SubstituteV2Test 가, 판정 규칙은 PuzzleTypeTest, NewKindsTest 가 확인합니다.

12웹 체험판

웹 모사 심사자가 차나 에뮬레이터 없이 흐름을 볼 수 있게 만든 정적 웹 페이지입니다. 실제 차량 신호가 아니라 화면 옆의 가상 차량 패널이 값을 만듭니다.

  • 구성. 빌드 과정 없는 정적 파일. 게임 엔진은 Kotlin 엔진을 JavaScript 로 옮긴 web/game.js 이고, web/selftest.mjs 가 Kotlin 테스트와 같은 시나리오로 두 엔진의 동작을 맞춥니다.
  • 화면 규격. 앱 창은 공식 dp 값 그대로(1 CSS px = 1dp) 그리고 차량 화면 전체를 브라우저 크기에 맞춰 줄입니다.
  • 주소 옵션. ?screen=S17_LAND 등 12종, ?mode=light, ?seed=35(오늘의 금고 판 고정), ?auto=1(자동 시연).
  • 저장. 기록, 배지, 일지, 차고 선택은 그 브라우저의 localStorage 에만 저장합니다. 서버로 보내는 것이 없습니다.
  • 웹에 없는 것. 출발 금고(갈림길, 주차 암호, 다시 탔어요)는 Android 앱에만 있습니다.
  • 음성. Android 앱은 기기의 TTS 엔진으로 읽고, 웹은 미리 합성해 둔 음성 파일을 재생합니다.

13알려진 한계

  • 실차 미실행. 실제 차량에서는 아직 실행하지 않았습니다. 검증은 Pleos Connect Emulator v2.1.0 까지입니다.
  • 기준 차량 가정. 아이오닉 9 의 Pleos Connect 탑재는 공식 근거를 찾지 못한 목표 플랫폼 가정입니다. 지원 좌석, 창문 영역은 차에서 capability 로 확정됩니다.
  • 에뮬레이터로 확인하지 못한 입력. 안전벨트(조작 카드 없음), 탑승 좌석, 조수석과 2열 창문, 창문 잠금, 주행 모드, 속도만으로의 차단.
  • 와이퍼 매핑. Low 작동은 확인했고 High, Auto 가 어떤 상태값으로 오는지는 확인이 필요합니다.
  • 비상등. Pleos SDK 의 방향지시등 값에 비상등이 없어 퍼즐에 쓰지 않습니다.
  • 충전 잔여 시간. SDK 에 API 가 없어 변화율로 추정합니다. 충전 속도가 크게 바뀌는 구간에서는 오차가 생깁니다.
  • 기어를 알려 주지 않는 차. 정지 화면에 계속 머뭅니다. 안전 쪽을 택한 결과입니다.
  • 음성. Android 표준 TextToSpeech 를 씁니다. Pleos TextToSpeech SDK 는 아직 쓰지 않았습니다.
  • 시스템 화면 모드. 앱 테마는 자체 6종이며 시스템의 라이트, 다크 모드를 따라가지 않습니다.
  • 알려진 빌드 이슈. Paparazzi 2.0.0-alpha04 와 Gradle 8.14 조합에서 :ui 의 HTML 테스트 리포트를 껐습니다. JUnit XML 과 Paparazzi 리포트는 정상입니다.
